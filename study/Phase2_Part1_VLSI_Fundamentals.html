DAY 15
CMOS Technology & Logic Gates
Understand the transistor — the fundamental building block of every digital chip. Learn how NMOS and PMOS pair to form CMOS logic, and how standard cells implement every Boolean function you'll ever route.
T
The MOSFET Transistor — Foundation of Everything
NMOS
N-type MOSFET
Gate = 1 → transistor ON (conducts). Gate = 0 → transistor OFF. Pulls output toward GND (0V). Made from P-type silicon with N-type source/drain regions. Fast but only pulls low.
PMOS
P-type MOSFET
Gate = 0 → transistor ON. Gate = 1 → transistor OFF. Pulls output toward VDD (supply voltage). Made from N-type silicon with P-type source/drain. Slower than NMOS, pulls high.
CMOS
Complementary MOS — why we pair them
CMOS = NMOS + PMOS always working opposite each other. When NMOS is ON, PMOS is OFF — and vice versa. This means: no DC current path, near-zero static power, full voltage swing (rail-to-rail). This is why all modern chips use CMOS.
KEY INSIGHT
Static power ≈ 0 in CMOS
At any stable logic state, either NMOS or PMOS is OFF, blocking DC current. Power is only consumed during switching (dynamic power = C·V²·f). This is why CMOS enabled battery-powered electronics.
¬
The CMOS Inverter — Simplest Gate, Deepest Lesson
CIRCUIT
PMOS on top, NMOS on bottom
VDD → PMOS source. PMOS drain → Output. Output → NMOS drain. NMOS source → GND. Both gates tied to Input. One transistor always OFF, preventing short circuit.
INPUT = 0
Output = 1 (VDD)
PMOS gate = 0 → PMOS ON → output connected to VDD. NMOS gate = 0 → NMOS OFF → output disconnected from GND. Result: output = VDD = logic 1.
INPUT = 1
Output = 0 (GND)
PMOS gate = 1 → PMOS OFF → VDD disconnected. NMOS gate = 1 → NMOS ON → output connected to GND. Result: output = 0V = logic 0.
PD RELEVANCE
The inverter is your timing reference
Inverter propagation delay (tp) is the benchmark cell in every technology node. When a PD tool reports "cell delay = 2 FO4", FO4 = delay of an inverter driving 4 identical inverters. Your entire timing budget is measured in inverter delays.
Memory Analogy
CMOS inverter = a seesaw with two kids. When one side goes up (NMOS ON, pulls to GND), the other must come down (PMOS OFF). They can never both be on the same side at the same time — that would short-circuit the power supply. This complementary action is why it's called Complementary MOS.
⊕
Standard Logic Gates — What PD Tools Place & Route
NAND2Output = NOT(A AND B). 2 series NMOS + 2 parallel PMOS. The most fundamental gate — NAND is logically complete (can implement any function). Fastest CMOS gate because PMOS pulls up in parallel.
PD: NAND is preferred over AND by synthesis tools because AND = NAND+INV = more transistors
NOR2Output = NOT(A OR B). 2 parallel NMOS + 2 series PMOS. Series PMOS makes it slower than NAND of same drive strength.
PD: NOR used for clock gating and reset logic where structure matters more than speed
INVOutput = NOT(A). Smallest CMOS gate (1 NMOS + 1 PMOS). Used massively as clock buffers (CLKBUF = 2 cascaded inverters for equal rise/fall).
PD: inverter chains drive all clock trees. If you see CLKBUF in a netlist, it's two inverters inside
AND2 / OR2NAND2 + INV / NOR2 + INV. Physically larger than NAND/NOR by 1 inverter. Synthesis tools prefer NAND/NOR for area efficiency.
PD: AND/OR gates cost ~33% more area than NAND/NOR equivalents — matters at 85% utilization
XOR2Output = A⊕B = (A AND NOT_B) OR (NOT_A AND B). Complex gate — requires ~8–12 transistors. Critical for adders and CRC logic.
PD: XOR gates are large, slow, and create timing-critical paths. Flag them for manual timing review
MUX2Output = S ? B : A. Select between two inputs. Implemented as 2 transmission gates + 1 inverter. Used for clock muxing and data path selection.
PD: clock MUXes are the most timing-critical cells — wrong placement = clock skew disaster
BUFOutput = A (non-inverting). Two cascaded inverters. Used to restore signal strength on long wires.
PD: the tool inserts BUFs automatically during placement to fix long-wire timing violations (buffering)
X
Drive Strength — X1, X2, X4, X8 Cells
WHAT IT IS
Wider transistors = more current
An X2 cell has transistors twice as wide as X1. It can charge/discharge the output capacitance twice as fast. INV_X1, INV_X2, INV_X4, INV_X8 are all the same function — different speeds and power.
TRADEOFF
Speed vs Area vs Power
X2 = 2× speed, 2× area, 2× dynamic power. You cannot get free speed. Upsizing a cell to fix a timing violation increases area and power — always check if it creates a new problem elsewhere.
PD USAGE
ECO upsizing — daily PD task
After placement, timing violations are fixed by "upsizing" cells: changing INV_X1 → INV_X2 → INV_X4 on the critical path. In Innovus: size_cell [get_cells inst_name] INV_X4. This is called an ECO (Engineering Change Order).
RULE OF THUMB
Start with X2, push to X4
Most netlists from synthesis use X2 for data paths. Clock cells use X4–X8. Never use X1 on timing-critical paths — marginal design. Never use X8 everywhere — bloats area.

DAY 16
Sequential Logic — Flip-Flops, Latches & Timing
Flip-flops are the memory elements of every digital design. Setup time, hold time, and clock-to-Q delay are the three timing parameters that define your entire PD timing closure problem. Master these completely.
D
The D Flip-Flop — The Heart of Every Digital Design
WHAT IS IT
A 1-bit memory element
A D flip-flop captures the value on its D (data) input at the rising edge of CLK and holds it at Q until the next rising edge. It is the building block of all registers, state machines, and pipelines.
PORTS
D, CLK, Q (and optionally QN, RN, SN)
D = data input. CLK = clock input. Q = data output. QN = inverted output. RN = active-low async reset. SN = active-low async set. In a netlist: DFFRQ_X2 reg0 (.D(d_in), .CK(clk), .Q(q_out), .RN(rst_n));
SETUP TIME (tsu)
Data must be stable BEFORE clock edge
Setup time is the minimum time D must be stable before CLK rises. Typically 50–150ps in 28nm. If violated: data is sampled incorrectly — metastability. This is the most common timing violation in PD.
HOLD TIME (th)
Data must be stable AFTER clock edge
Hold time is the minimum time D must remain stable after CLK rises. Typically 0–50ps. If violated: data is corrupted after capture. Hold violations are fixed by adding buffers on the data path — they cannot be fixed by faster logic (unlike setup).
CLK-TO-Q (tCQ)
Delay from clock edge to output changing
After CLK rises, Q changes after tCQ delay. Typically 100–300ps. This consumes part of the clock period budget. Total path: tCQ + logic_delay + wire_delay ≤ clock_period - tsu.
SLACK
Your timing margin
Slack = available_time - required_time. Positive slack = timing MET (you have margin). Negative slack = VIOLATED (path is too slow). WNS = Worst Negative Slack — the number you chase to zero in every PD project.

Memory Analogy — Setup & Hold
Think of a photo booth with a camera: The camera fires (= clock edge) at a fixed moment. Setup time = "stand still at least 0.1s before the flash" — you need to be in position before the photo. Hold time = "don't move for at least 0.05s after the flash" — stay still while the image registers. If you walk in too late (setup violation) or walk away too fast (hold violation), the photo is blurred (metastability). Physical design engineers spend 60% of their time ensuring no signal reaches any flip-flop at the wrong moment.

Timing Waveform — Reading the Diagram
CLK0↑111111↑1
D (data in)000→111 ✓1111
Q (data out)000 +tCQ000000 +tCQ1
SETUP WINDOW
D must be stable before ↑CLK
D changed to 1 at column 4. Clock rises at column 9. D was stable from column 4 to 9 — well within setup window. ✓ Setup MET.
CLK-TO-Q
Q changes after tCQ delay
Clock edge at column 9. Q becomes 1 at column 10 (after tCQ delay). The output only changes in response to the clock — not combinational.
L
Latch vs Flip-Flop — Know the Difference
D Flip-FlopEdge-triggered. Captures D only at clock edge (rising or falling). Q is stable between clock edges. Used in 99% of synchronous digital designs.
PD: standard cell name pattern: DFFR*, DFF_*, FF* — all edge-triggered
D LatchLevel-sensitive. When CLK=1 (enable=1), Q follows D continuously (transparent). When CLK=0, Q holds last value. Used in specific low-power and ASIC designs.
PD: latches are harder to time-analyse — STA tools need special handling for latch-based designs
Why FFs winEdge-triggering means data is captured at a single predictable instant. Timing analysis is deterministic. Latches are transparent for a window of time — harder to constrain and route.
Interview question: "Why do we use flip-flops instead of latches?" — Answer: predictable timing, easier STA

# Day 16 — Timing path calculator proc analyse_path {period tcq gate_delays wire_delay tsu th} { # Arrival time set logic_sum [expr {[tcl::mathop::+ {*}$gate_delays] + $wire_delay}] set arrival [expr {$tcq + $logic_sum}] # Required times set setup_req [expr {$period - $tsu}] set hold_req [expr {0 + $th}] # Slacks set setup_slack [expr {$setup_req - $arrival}] set hold_slack [expr {$arrival - $hold_req}] puts "\n========= Timing Analysis =========" puts [format " Clock period : %.3f ns" $period] puts [format " CLK-to-Q (tCQ) : %.3f ns" $tcq] puts [format " Logic delay : %.3f ns" [expr {$logic_sum - $wire_delay}]] puts [format " Wire delay : %.3f ns" $wire_delay] puts [format " Arrival time : %.3f ns" $arrival] puts [format " Setup required : %.3f ns" $setup_req] puts [format " Hold required : %.3f ns" $hold_req] puts [string repeat - 36] if {$setup_slack >= 0} { puts [format " SETUP : MET (+%.3f ns slack)" $setup_slack] } else { puts [format " SETUP : VIOLATED (%.3f ns)" $setup_slack] } if {$hold_slack >= 0} { puts [format " HOLD : MET (+%.3f ns slack)" $hold_slack] } else { puts [format " HOLD : VIOLATED (%.3f ns)" $hold_slack] } } # --- Test Case 1: 500MHz, 5-gate path --- # period=2ns tCQ=0.15 gates={0.08 0.07 0.09 0.08 0.06} wire=0.12 tsu=0.07 th=0.03 analyse_path 2.0 0.15 {0.08 0.07 0.09 0.08 0.06} 0.12 0.07 0.03 # --- Test Case 2: 1GHz, same path — observe violation --- analyse_path 1.0 0.15 {0.08 0.07 0.09 0.08 0.06} 0.12 0.07 0.03

  • 02Modify Test 2: reduce gate delays to {0.04 0.03 0.04 0.03 0.03} — this simulates upsizing cells. Does it now pass at 1GHz?

RTL-to-GDSII Flow & PD File Ecosystem
The complete journey from a Verilog description to a manufacturable chip. Understand every step, who owns it, what the inputs/outputs are — and master every file format you will encounter in a PD job.
↓
The Complete RTL-to-GDSII Flow — Every Step
RTL (.v files)
← Designer writes this. Behavioural description.
↓ Logic Synthesis (Synopsys DC / Cadence Genus)
Gate Netlist (.v)
← RTL mapped to library cells. No timing met yet.
↓ Physical Design begins here
Floorplan
← Define die area, place macros, I/O pins
↓
Power Planning
← VDD/VSS rings, stripes, well taps
↓
Placement
← Assign XY coordinates to all standard cells
↓
Clock Tree Synthesis
← Balance clock distribution to all FFs
↓
Routing
← Connect all nets with metal wires on layers
↓
Signoff (STA/DRC/LVS)
← Verify timing, physical rules, netlist match
↓
GDSII / OASIS
← The final file sent to the foundry for fabrication
ℹ
Where Physical Design begins and ends: PD engineers own everything from the gate netlist to the GDSII file. Synthesis (RTL→netlist) is owned by the logic design team. Signoff sign-off is shared between PD and the design verification team. The PD engineer's primary job is to implement the netlist as a physical layout that meets timing, area, and power targets.
📄
Every PD File Format You Will Ever Encounter
.v / .sv
Verilog / SystemVerilog
RTL source (behavioural) or gate-level netlist (structural). Human-readable. PD reads the gate netlist, not the RTL.
.sdc
Synopsys Design Constraints
TCL-format timing constraints. Defines clocks, input/output delays, false paths, multicycle paths. PD engineers write and maintain this file throughout the project.
.lef
Library Exchange Format
Abstract view of standard cells and macros. Describes cell footprint, pin locations, obstruction layers. PD tool uses this for placement — not the transistor details.
.lib / .db
Liberty Timing Library
Timing and power data for each cell at each PVT corner. Contains setup/hold/tCQ values, input capacitance, leakage power. The STA tool reads this to compute path delays.
.def
Design Exchange Format
Physical layout data: die area, row placement, cell placement XY coordinates, routing (if post-route). The main output of each PD step — grows from floorplan through route.
.gds / .gdsii
Graphic Data System II
Binary format. The final physical layout including all metal layers, vias, diffusion, poly. This file is sent to the foundry (TSMC, Samsung) for mask generation and fabrication.
.spef
Standard Parasitic Extraction Format
Post-route wire resistances and capacitances extracted from the actual layout. STA uses this for accurate timing — pre-route timing uses estimates only.
.vcd / .saif
Switching Activity Files
Simulation toggle rates for each net. Power analysis (Innovus, PrimeTime PX) uses this to compute dynamic power. Without it, power analysis uses default toggle rates (often wrong).
.upf / .cpf
Unified/Common Power Format
Defines power domains, voltage islands, isolation cells, retention FFs for low-power designs. Written in TCL format. Required for any design with multiple supply voltages.
.rpt
Report files
Tool-generated text reports: timing (slack, path details), area (cell counts), DRC violations, power estimation. You grep these files — every PD run generates dozens.
.tcl
TCL Script
Your flow scripts, constraint scripts, ECO scripts, utility procs. Every PD tool command is a TCL command. The scripts you write control the entire flow.
.oas / .oasis
OASIS (replaces GDSII)
Modern foundry layout format — more compact than GDSII for advanced nodes. At 7nm and below, GDSII files are too large; OASIS reduces file size by 10–30×.

QUIZ
Part 1 Self-Assessment — VLSI Fundamentals
10 questions covering CMOS, logic gates, flip-flop timing, and the PD flow. These exact question types appear in physical design engineer technical interviews.
Q1. In a CMOS NAND2 gate, both inputs are HIGH (1,1). What is the state of the NMOS and PMOS networks?
With both inputs=1: both NMOS transistors are ON (their series path to GND is complete), and BOTH PMOS transistors are OFF (their parallel path to VDD is broken). Result: output = 0. Remember NAND: needs BOTH NMOS ON to pull low; needs EITHER PMOS ON to pull high. NAND(1,1)=0.
Q2. A flip-flop has setup time tsu=0.08ns, hold time th=0.03ns, and tCQ=0.15ns. The clock period is 2.0ns. A combinational path has total delay (logic + wire) = 1.82ns. What is the setup slack?
Setup slack = required_time - arrival_time. Required = period - tsu = 2.0 - 0.08 = 1.92ns. Arrival = tCQ + delays = 0.15 + 1.82 = 1.97ns. Slack = 1.92 - 1.97 = -0.05ns. VIOLATED by 50ps. Fix: upsize cells on this path to reduce logic delay, or improve placement to reduce wire delay.
Q3. What is the difference between a hold time violation and a setup time violation? How is each fixed in PD?
Setup violation = data arrives LATE (path is too slow) → fix by making logic faster: upsize cells, add buffers to reduce wire delays, improve placement proximity, or pipeline to break the path. Hold violation = data arrives TOO FAST (before hold time window closes) → fix by ADDING delay (insert buffers on data path). Critical: hold violations must be fixed WITHOUT increasing clock frequency — they're independent of period.
Q4. In the RTL-to-GDSII flow, which file is sent to the semiconductor foundry for chip manufacturing?
The foundry receives the GDSII (.gds or .oas for advanced nodes) file — the binary physical layout with every metal layer, via, transistor polygon, and text label encoded precisely. TSMC/Samsung/GlobalFoundries reads this to create the photolithographic masks (one per metal layer) used to etch patterns into silicon wafers. This is the final deliverable of the entire design flow.
Q5. Why does a PD tool use .lef files rather than the full transistor-level SPICE netlists for cell placement?
LEF is an abstract view — it describes cell dimensions, pin positions, and which metal layers are blocked by the cell. The placer only needs: "how big is this cell, where are its pins, what metal layers does it use?" A full transistor-level view of 50,000 unique cells × millions of instances would be terabytes of data that the tool can't process in reasonable time. This is the principle of abstraction: use only the level of detail each task requires.

01
Combinational vs Sequential Logic

On Day 1 you studied gates — NAND, NOR, INV. Those are combinational logic circuits. Today we introduce sequential logic — circuits that have memory. Together, these two categories make up 100% of the digital logic inside any chip you will ever work on as a PD engineer.

The Fundamental Difference

PropertyCombinational LogicSequential Logic
Output depends onCurrent inputs onlyCurrent inputs + past state (memory)
MemoryNoneYes — stores 1 bit per element
Clock neededNoYes (for synchronous designs)
ExamplesNAND, NOR, adder, MUX, encoderLatch, flip-flop, register, FSM, memory
In timing analysisLogic cones between flip-flopsLaunch and capture endpoints
🧠 Analogy

Combinational logic is like a light switch — flip it and the light responds immediately. Sequential logic is like a combination lock — what matters is the history of inputs (the sequence of numbers you dialed), not just what you're pressing right now. The lock "remembers" its state.

Why This Matters Enormously for PD Engineers

In Physical Design, flip-flops are the endpoints of every timing path. When you run Static Timing Analysis (STA) — which you will do constantly — the tool checks whether data arrives at each flip-flop's input at the right time relative to the clock. That "right time" is defined by setup time and hold time — which you will master today.

A typical 1GHz processor chip has hundreds of thousands to millions of flip-flops. Your job is to place them, route wires between them, and ensure timing is met at every single one. Understanding what a flip-flop is — down to the transistor level — is not optional. It is the foundation of your career.

⚡ PD Engineer Context

When a timing report shows "Endpoint: counter_reg[3]/D" — that "/D" is the Data input of a D flip-flop. When it shows "Startpoint: counter_reg[3]/Q" — that "/Q" is the output. When it says "CK" — that is the clock pin. Every path in a timing report starts and ends at sequential elements. Today you learn exactly what those elements are.

02
SR Latch — The First Memory Cell

The SR Latch (Set-Reset Latch) is the simplest sequential circuit possible. It is the fundamental memory cell from which all latches and flip-flops are built. Understanding it gives you an intuition for how all storage works in silicon.

Construction from Cross-Coupled NAND Gates

The most common implementation uses two NAND gates with their outputs feeding back to the other gate's input — this cross-coupling is what creates memory:

SR LATCH (NAND Implementation) S ──────┬────[NAND]──── Q │ ↑ └──────── ┘ ← Cross-coupled feedback ┌──────── ┐ │ ↓ R ──────┴────[NAND]──── Q̄ (Q-bar, complement of Q) The output of each NAND feeds back as input to the other NAND. This feedback loop is what creates bistable behavior (two stable states).

Truth Table — NOR-based SR Latch (Active High)

The NOR-based version is easier to analyze first (inputs are active-HIGH):

SRQ (next)Q̄ (next)State
00Q (hold)Q̄ (hold)HOLD — no change
1010SET — Q goes HIGH
0101RESET — Q goes LOW
110*0*FORBIDDEN — both outputs 0, breaks Q̄=NOT(Q)

Why the S=1, R=1 State is Forbidden

When both S and R are 1, both outputs are forced LOW simultaneously — so Q=0 AND Q̄=0. But by definition Q̄ must be the complement of Q (i.e., Q̄=NOT Q). Having Q=Q̄=0 violates this invariant and makes the circuit's next state unpredictable when inputs return to 0. This forbidden state leads directly to metastability — which you will study in Section 8.

🧠 Analogy

Imagine a light switch wired to two people: Person S (Sets it ON) and Person R (Resets it OFF). If both do nothing (S=R=0) — the light stays as it was. If only S acts — light turns ON. If only R acts — light turns OFF. If BOTH act simultaneously with equal force — you get a tug-of-war with no valid winner. That's the forbidden state: the output races between 0 and 1 unpredictably.

The Key Property: Bistability

The cross-coupled feedback creates two stable equilibrium states: Q=1,Q̄=0 or Q=0,Q̄=1. The circuit holds one state indefinitely with no power needed to maintain it (unlike a capacitor, which leaks). This is static storage — the basis of all SRAM cells and flip-flops.

📌 PD Relevance

Every SRAM memory bitcell (used in caches, register files) is essentially a 6-transistor cross-coupled inverter pair — the CMOS analog of the SR latch. When you place memory macros during floorplanning, you are placing billions of these cells. The forbidden state / metastability concern you're learning now is the same physics that governs SRAM sense amp timing.

03
D Latch — Level Sensitive Storage

The SR Latch has a serious problem: the forbidden state. The D Latch solves this by reducing the two independent inputs (S and R) to a single data input (D), with R always equal to NOT(D). This eliminates the forbidden state entirely.

D Latch Circuit

D LATCH D ────┬────────────[NAND]──── Q │ ↑ [INV] (cross-coupled) │ ↓ └────────────[NAND]──── Q̄ EN ──── (gate enables both NAND paths) Simpler view: D ───────[ ]──────── Q EN ──────[ Latch ] [ ]──────── Q̄ When EN=1 (HIGH): latch is TRANSPARENT — Q follows D When EN=0 (LOW): latch is OPAQUE — Q holds last value

Truth Table

ENDQ (next)Description
111Transparent — Q follows D=1
100Transparent — Q follows D=0
0XQ_prevOpaque — Q holds previous value

The Critical Problem: Transparency and Timing Hazard

Because a latch is transparent while EN is HIGH, data can "ripple through" multiple latches if EN is held HIGH for too long. This makes timing analysis complicated — data can pass through a latch mid-clock-cycle, creating what's called a timing race condition.

⚠️ Danger: Latch Transparency

In a system with multiple D latches, if the enable is HIGH across multiple latch stages simultaneously, data can race through the entire chain in a single cycle. This makes functional verification extremely difficult and timing analysis complex. This is why synchronous digital design almost universally uses D Flip-Flops (edge-triggered) instead of latches for state storage.

When Latches Are Used in PD

Despite the complexity, latches are not obsolete. They appear in:

  • Time-borrowing: in high-performance pipelines, latches allow a fast stage to "borrow" time from the next stage — a specific optimization technique
  • SRAM bitcell: the core of all cache memory
  • ICG (Integrated Clock Gate): the latch inside a clock gate cell holds the enable signal, preventing glitchy gated clocks — you'll see this constantly in CTS
  • Reset synchronizers: for clean reset release across clock domains

04
D Flip-Flop — Edge-Triggered Storage

The D Flip-Flop (DFF) is the single most important sequential element in digital design. Every register, every pipeline stage, every state machine is built from DFFs. As a PD engineer, every timing path you analyze starts at a DFF output (Q) or ends at a DFF input (D).

How a D Flip-Flop is Built

A D Flip-Flop is constructed from two D latches in a master-slave configuration:

D FLIP-FLOP = MASTER LATCH + SLAVE LATCH CLK CLK │ │ ▼ ▼ D ──── [Master D Latch] ──── [Slave D Latch] ──── Q EN = CLK EN = CLK̄ Master: transparent when CLK=0, opaque when CLK=1 Slave: transparent when CLK=1, opaque when CLK=0 At CLK rising edge (0→1): Master becomes OPAQUE (locks current D value) Slave becomes TRANSPARENT (passes captured D to Q) Result: Q captures D exactly at the rising clock edge and holds it for the entire clock cycle

Key Behavior: Edge-Triggered

Unlike a latch (level-sensitive), the DFF only captures data at one instant — the rising clock edge (for a positive-edge-triggered DFF). Between edges, the output Q is stable regardless of what D does. This makes timing analysis clean and predictable — which is exactly why synchronous design dominates the industry.

TIMING DIAGRAM — D Flip-Flop (Positive Edge Triggered) CLK : ___ ___ ___ ___ ___ | | | | | | | | | | | |_| |_| |_| |_| |_ ↑ ↑ ↑ ↑ ↑ edge1 edge2 edge3 edge4 edge5 ← data captured at each ↑ D : ─────────┐ ┌──────┐ └─────┘ └────── ← D changes freely Q : ─────────────────┐ ┌───── ← Q only changes AFTER rising edge └─────┘ captures whatever D was at that instant Notice: D changed between edge1 and edge2 → Q updates at edge2 only D was HIGH at edge3 → Q goes HIGH, holds until edge where D=LOW

CMOS Implementation of D Flip-Flop

In standard cell libraries, a DFF is implemented using transmission gates (pass transistors) rather than NAND latches — this gives a more compact and faster implementation:

CMOS DFF (Transmission Gate Implementation) D ──[TG1]──┬──[INV1]──[TG2]──┬──[INV3]──[TG3]──┬──[INV5]── Q CLK̄ CLK │ │ CLK CLK̄ │ [INV2] [INV4] [INV6] │ │ (feedback) │ └──────────────────┘ └──(feedback) TG = Transmission Gate (NMOS + PMOS in parallel, controlled by CLK and CLK̄) ~20–28 transistors total in a typical DFF implementation Key outputs used in PD timing analysis: D → Data input (setup/hold time measured here) Q → Data output (clock-to-Q delay starts from clock edge) CK → Clock input (reference for all timing measurements) QN → Inverted Q output (available in some DFF variants)

Important DFF Variants You'll See in Netlists

Setup Time — The Most Critical Timing Spec

You will fix setup violations every single day as a PD engineer. Understanding what setup time physically means — not just memorizing the definition — is what separates engineers who debug timing quickly from those who struggle.

Definition

Setup time (T_su) is the minimum amount of time that the data input D must be stable and valid BEFORE the active clock edge arrives at the flip-flop.

🧠 Analogy — The Train

Setup time is like a train departure. The train (clock edge) departs at a fixed time. If you (data) arrive at the platform fewer than 5 minutes before departure, you miss the train. The "5 minutes" is setup time — the minimum time you must be present before the clock edge. Arrive late → you miss the capture → the flip-flop captures garbage → chip fails.

Why Setup Time Exists — The Physics

Recall that a DFF is built from two latches with transmission gates. When the clock edge arrives:

  1. The master latch must transition from transparent to opaque
  2. The transmission gates switch states — this takes finite time (TG propagation)
  3. The internal nodes of the master latch must reach their stable final values before the slave latch opens

If data D arrives too late (less than T_su before the clock edge), the master latch's internal nodes haven't settled — the DFF captures an incorrect value. This is a setup violation.

Setup Time in a Timing Path

REGISTER-TO-REGISTER TIMING PATH (Most Common) ┌─────────┐ combinational logic ┌─────────┐ │ Launch │ Q ──────────[gates]─────────────── D│ Capture │ │ FF │ │ FF │ │ CK│◄── Launch clock CK│◄── Capture clock └─────────┘ └─────────┘ │ │ Launch edge Capture edge (CLK rises here) (CLK rises here, T_period later) Timeline: t=0 : Launch clock edge rises t=Tcq : Launch FF output Q transitions (clock-to-Q delay) t=Tcq : Data starts propagating through combinational logic t=Tcq+Tlogic : Data arrives at Capture FF's D input Required: Data must arrive by T_period - T_setup - T_uncertainty Actual: Data arrives at Tcq + Tlogic + T_net Setup Slack = (T_period - T_setup) - (Tcq + Tlogic + T_net) = Required Arrival Time - Actual Arrival Time Positive slack → PASS ✓ Negative slack → VIOLATION ✗ — must be fixed before tapeout

Setup Check Equation

Setup Timing Check
T_launch + Tcq + T_logic + T_net ≤ T_capture - T_setup - T_uncertainty Where: T_launch = time of launch clock edge (e.g. 0) Tcq = clock-to-Q delay of launch FF (from library) T_logic = total propagation delay through combinational logic T_net = wire delay (parasitic RC, extracted from layout) T_capture = time of capture clock edge (= T_launch + T_period) T_setup = setup time of capture FF (from library) T_uncertainty = clock uncertainty (jitter + skew margin) Setup Slack = T_capture - T_setup - T_uncertainty - (T_launch + Tcq + T_logic + T_net) = Required Arrival Time - Actual Arrival Time

How to Fix Setup Violations

Fix MethodWhat It DoesTrade-off
Upsize cellsUse higher drive-strength cell (X2, X4) → faster switchingMore area, more power
Replace with faster VtSwap HVT → SVT or LVT cell → lower Vt → fasterIncreased leakage power
Buffer/rebuffer netInsert buffer on long wire → reduces net delayMore cells, slight area
Logic restructuringReduce logic depth (fewer gate levels on critical path)Can change netlist significantly
Useful clock skewMake capture clock arrive later → more time for dataCan hurt other paths
Reduce clock frequencyIncrease T_period → more time availablePerformance loss — last resort
⚡ Key Interview Insight

Setup violations are a function of frequency — they disappear if you run the chip slower. This is why a chip with setup violations is called "frequency-limited." Every ns you reduce the clock period helps setup. Hold violations, on the other hand, are independent of frequency — they exist at any speed. This fundamental difference drives completely different fix strategies.

Hold Time — The Insidious Violation

Hold time is the second pillar of timing analysis and arguably the more dangerous of the two violations — because unlike setup, hold violations cannot be fixed by running the chip slower. They exist at every frequency and will cause functional failure at all speeds.

Definition

Hold time (T_hold) is the minimum amount of time that data at input D must remain stable and unchanged AFTER the active clock edge. The flip-flop is still in the process of "latching" the data during this window — if data changes before this time expires, the captured value may be corrupted.

🧠 Analogy — The Scanner

Hold time is like a document scanner. After you press SCAN (clock edge), you must keep the document still for at least T_hold seconds while the scanner reads it. If you yank the paper out too early — the scan captures a blurred, corrupted image. The data "moved" before the capture was complete.

Why Hold Time Exists — The Physics

At the clock edge, the transmission gates inside the DFF are switching. During this transition:

  1. The master latch is becoming opaque — but this takes a finite time
  2. The slave latch is becoming transparent — it begins passing data to Q
  3. If data D changes during this window, the partially-transparent master latch may partially capture the new data, resulting in an unknown intermediate state

The Hold Check Equation

Hold Timing Check
T_launch + Tcq + T_logic + T_net ≥ T_capture + T_hold + T_uncertainty For a same-edge capture (both FFs launch and capture on same edge): Hold Slack = (Tcq + T_logic + T_net) - (T_hold + T_uncertainty) = Actual data arrival - Minimum required hold time Must be ≥ 0 for no violation

Hold Violations: When and Why They Occur

ScenarioWhy Hold Violation Happens
Short combinational pathIf logic between two FFs is very fast (or zero — direct connection), data arrives at capture FF too quickly after clock edge — before hold time expires
Zero-logic path (direct FF-to-FF)No combinational delay → data at capture D changes almost immediately after launch Q → most common source of hold violations
Post-CTS hold violationsAfter CTS, actual clock delays are inserted. If launch FF gets clock earlier than capture FF, the effective "time available" shrinks → hold violations appear that weren't there pre-CTS
Negative clock skewCapture FF clock arrives before launch FF clock → data can arrive too quickly at capture before hold window closes

How to Fix Hold Violations

⚠️ The Golden Rule of Hold Fixing

NEVER fix a hold violation by modifying the clock path. ALWAYS add delay to the DATA path. Adding buffers to the clock path to delay the clock on the capture side will create hold violations on other paths and can cascade into an unfixable mess.

Fix MethodMechanismNotes
Insert delay buffers (BUFD, DLYND)Add delay cells on the data path to increase Tlogic + TnetMost common PD fix. Adds area.
Insert inverter pairsINV+INV = delay + no logic changeFast to implement in ECO
Route data net on higher resistance layerIncreases RC delay of wireDone during ECO routing
Use lower-drive-strength cellsSmaller cells drive more slowly → adds delay naturallyOnly if timing allows elsewhere

Setup vs Hold — The Complete Comparison

PropertySetup ViolationHold Violation
When does data fail?Arrives TOO LATE before clock edgeLeaves TOO EARLY after clock edge
Frequency dependent?Yes — reduce freq → setup fixes itselfNo — exists at ALL frequencies
Which is more dangerous?Less — can prototype at lower speedMore — chip fails completely at any speed

⚡ PD Engineer Reality

In a real PD project: after CTS, hundreds to thousands of hold violations appear because inserting real clock buffers changes the relative clock arrival times across the chip. PD tools (ICC2, Innovus) automatically fix holds by inserting delay buffers. Your job is to review the reports, ensure the fixes didn't create new setup violations, and verify that hold fixing didn't cause routing congestion in critical regions.

07
Clock-to-Q Delay & Complete Timing Path Analysis

Now that you understand setup and hold time, let's build a complete picture of all the timing parameters involved in a register-to-register path — the bread and butter of STA.

Clock-to-Q Delay (Tcq)

Tcq is the propagation delay from the active clock edge at CK to when the output Q settles to its new stable value. It is a fixed parameter from the cell library — the PD tool reads it from the .lib file.

  • Tcq depends on: load capacitance at Q, input slew on CK, temperature, voltage (from PVT corners)
  • Typical Tcq range: 100ps – 400ps at 28nm, faster at 7nm
  • There are two Tcqs: Tcq_rise (Q transitions 0→1) and Tcq_fall (Q transitions 1→0)
📌 In Timing Reports

In a PrimeTime or OpenSTA timing report, you will see a line like:
DFFX1/CK → DFFX1/Q (rise) 0.24ns
That 0.24ns is Tcq. It is the first delay in every timing path and eats into your available clock period before data has even entered the combinational logic.

All Timing Parameters Together

08
Metastability & Clock Domain Crossing

Metastability is one of the most important and subtle concepts in digital design. It causes chip failures that are intermittent and extremely difficult to reproduce — making it a nightmare for any design team. As a PD engineer, your awareness of metastability shapes how you handle certain types of design structures.

What is Metastability?

Recall that a flip-flop captures data at the clock edge. Setup and hold times define a forbidden window around the clock edge. If data transitions happen to change exactly within this window, the DFF's internal circuit is in an indeterminate state — it cannot decide between 0 and 1. This is metastability.

METASTABILITY WINDOW Clock Edge ↓ ───────────────────────────────────────────────────► time │←T_hold→│ │←T_setup→│ └─────────┴───┴─────────┘ FORBIDDEN WINDOW (Data must NOT change here) If D transitions within this window: → FF enters metastable state → Output Q hovers near VDD/2 (indeterminate) → Eventually resolves to 0 or 1 after an unpredictable time → Resolution time can be picoseconds OR microseconds (probabilistic!) Key property: the FF ALWAYS eventually resolves — but if resolution takes longer than one clock period, the downstream logic samples VDD/2 → logic malfunction.

Mean Time Between Failures (MTBF)

Metastability cannot be completely eliminated — only its probability of causing failure can be reduced. The metric is MTBF:

Metastability MTBF
MTBF = exp(T_resolution / τ) / (f_clk × f_data × T_window) T_resolution = time available for FF to resolve (usually 1 clock period) τ = technology-dependent time constant (~20-50ps) f_clk = clock frequency f_data = rate of data transitions T_window = metastability window width (≈ T_setup + T_hold)

Clock Domain Crossing (CDC)

The most common cause of metastability in real chips is Clock Domain Crossing (CDC) — when data generated in one clock domain (e.g., 100MHz) is captured by a flip-flop in a different clock domain (e.g., 150MHz). Because the two clocks are asynchronous (no fixed phase relationship), the data can arrive at any time relative to the capture clock edge.

CLOCK DOMAIN CROSSING (CDC) Domain A (100MHz) Domain B (150MHz) ───────────────── ───────────────── CLK_A: ┌─┐ ┌─┐ ┌─┐ CLK_B: ┌──┐ ┌──┐ ┌──┐ │ │ │ │ │ │ │ │ │ │ │ │ ┘ └─┘ └─┘ └─ ┘ └──┘ └──┘ └ FF_A ──────────────────────────────────► FF_B ↑ DANGER: data from CLK_A domain captured by CLK_B — not synchronous! Metastability risk! SOLUTION: 2-Flop Synchronizer FF_A ──► [FF_sync1] ──► [FF_sync2] ──► rest of CLK_B domain CLK_B CLK_B FF_sync1 may go metastable, but has nearly 1 full CLK_B period to resolve FF_sync2 almost certainly sees a valid 0 or 1 → safe capture This is the standard 2-FF synchronizer — used everywhere in real chips

PD Engineer's Role in CDC

  • Identify CDC paths: formal CDC verification tools (Cadence JasperCDC, Synopsys SpyGlass) check for unsynchronized CDC signals
  • Implement synchronizer structures: 2-FF synchronizer, FIFO-based synchronizer, handshake synchronizer — based on data rate and latency requirements
  • Placement of synchronizer FFs: synchronizer flip-flops must be placed close together (minimal routing delay between the two FFs) to maximize MTBF
  • False path setting: CDC paths should be marked as false paths in SDC (set_false_path -from CLK_A -to CLK_B) since standard STA cannot check them meaningfully
✅ Key Takeaway

Metastability cannot be eliminated — but it can be made statistically negligible. A well-designed 2-FF synchronizer targeting 1000-year MTBF is more than adequate for any real product. The PD engineer's job is to recognize CDC structures in the netlist, ensure they are properly constrained in SDC, place synchronizer FFs close together, and ensure CDC analysis tools give a clean report before tapeout.

Cross-coupled gates = bistable memory. S=SET, R=RESET, S=R=1 = FORBIDDEN (metastability risk). Foundation of all storage.

Tcq

WNS / TNS
WNS = worst single path slack (how bad is the worst). TNS = sum of all violations (how much total work to fix). Both must be 0 at tapeout.
